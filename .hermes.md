# Contexto persistente de TudaGPX

- Propietario no técnico: asumir decisiones habituales e implementar y probar sin pedir permiso entre tareas. Consultar solo dudas importantes de producto, acciones sensibles o bloqueos reales.
- Trabajar únicamente en este repositorio y en el profile tudagpx. Conservar cambios locales ajenos.
- Rama de desarrollo: desarrollo/primera-version-local. No cambiar main, fusionar, publicar, conectar producción ni subir cambios sin autorización. Se permiten commits locales descriptivos.
- Primera prioridad: una web local que se pueda probar, no documentación sin software.
- React + Vite + Leaflet se conservan. Entrada local: src/LocalApp.jsx; App.jsx y los componentes de Supabase anteriores se conservan como referencia y no se cargan en la aplicación local.
- Persistencia provisional: IndexedDB, sin cuentas ni backend. No activar Supabase ni leer credenciales. Evolución prevista: PostgreSQL/PostGIS local, Neon en servidor, Vercel solo con autorización.
- Original GPX inmutable: routes[].originalBase64 conserva bytes exactos y routes[].original el texto interpretado. Borradores trabajan sobre copias. Guardar proyectos añade snapshots, no reemplaza versiones. No añadir borrado automático ni modificar originales al editar.
- Segmentos buscados por intersección geográfica de líneas con la vista. Selección independiente de la vista. Edición sin exigir continuidad; validación solo al revisar/exportar. Al crear y editar, seguir caminos por defecto, con modo libre opcional. BRouter solo tras consentimiento visible por sesión; no recalcular todo el GPX ni conectar elementos separados silenciosamente.
- Cartografías oficiales del componente MapaBase.jsx: IGN Base, MTN, PNOA máxima actualidad y OSM, con atribuciones.
- Interfaz: mapa prioritario, cabecera/pie compactos y biblioteca ocultable con ☰. Edición directa al estilo de interacción de gpx.studio: anclas arrastrables, inserción entre puntos, menú contextual y recorte visual; no volver al flujo principal basado en índices numéricos. Referencia y pruebas: docs/EDITOR_VISUAL.md.
- Dos pestañas principales: «Ver rutas» (solo visualización, filtros de nombre/actividad/distancia/desnivel/zona y superposición) y «Editar» (carga de rutas y segmentos, borrador, proyectos y herramientas). No mostrar geometría ni controles del borrador en el visor. Cambiar de pestaña conserva trabajo y selecciones sin remontar Leaflet; los filtros no alteran la selección superpuesta.
- Leer docs/PROGRESO.md y docs/ARQUITECTURA.md para estado y limitaciones. README.md explica uso y arranque.
- Verificar con npm run lint, npm run build y npm test. Pruebas Playwright en Chrome local; el puerto 5173 debe corresponder a este repo. No usar servicios simulados para dar por verificadas las cartografías.
- Mantener el servidor ligado a 127.0.0.1:5173. La dirección estable evita separar los datos de IndexedDB por origen. Copias JSON descargables protegen frente al borrado del navegador.
